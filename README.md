# tui-ssh-manager

Менеджер SSH-соединений для терминала. Позволяет хранить адреса серверов, группировать их по папкам и назначать профили аутентификации. Соединения и учётные данные сохраняются в одном зашифрованном файле.

При подключении приложение передаёт терминал системному OpenSSH. После выхода с сервера возвращается список соединений. Для нескольких одновременных подключений можно запустить менеджер в разных окнах или вкладках терминала.

Интерфейс на русском языке. В нём есть поиск, вкладки, браузер файлов и карточка выбранного объекта. Компоновка подстраивается под размер окна.

## Возможности

- Создание и редактирование соединений, профилей аутентификации и вложенных папок.
- Несколько профилей для одного соединения, профиль по умолчанию и наследование от папки.
- Вход через SSH-agent, локальный ключ, ключ из хранилища или сохранённый пароль.
- Интерактивный ввод OTP и подтверждение ключа сервера.
- Блокировка хранилища по таймауту и смена главного пароля.
- Зашифрованные резервные версии, экспорт и объединение конфликтных копий.
- Работа с файлом в папке облачного клиента.

Проект находится на стадии первой рабочей версии. Работа интерфейса и SSH-аутентификации проверена на macOS. Сборки для Linux создаются для arm64 и amd64; проверка работы непосредственно на Linux ещё предстоит.

## Требования

Для запуска нужны macOS или Linux, OpenSSH (`ssh` в PATH) и интерактивный терминал с поддержкой ANSI и UTF-8.

Для сборки нужны Go 1.24 или новее и `make`. Для терминального теста также нужны Python 3 и `ssh-keygen`.

## Сборка и запуск

Из каталога проекта:

```sh
make build
./bin/sshm
```

При первом запуске задайте главный пароль длиной не менее 10 символов. Приложение создаст хранилище по адресу:

```text
~/.config/sshm/connections.sshvault
```

Путь к открытому файлу отображается вверху экрана. Можно указать другой файл:

```sh
./bin/sshm -vault "$HOME/Cloud/SSH/connections.sshvault"
```

Чтобы установить собранный бинарник для своего пользователя:

```sh
mkdir -p "$HOME/.local/bin"
install -m 755 bin/sshm "$HOME/.local/bin/sshm"
```

Добавьте `~/.local/bin` в PATH вашей оболочки, если этот каталог ещё не указан в нём. После этого приложение можно запускать командой `sshm`.

Каталог блокируется после пяти минут бездействия. Таймаут можно изменить или отключить:

```sh
sshm -lock-after 15m
sshm -lock-after 0
```

После долгой SSH-сессии приложение предложит снова разблокировать хранилище. Во время заполнения формы и при несохранённых изменениях автоматическая блокировка приостанавливается.

Все параметры запуска доступны через `sshm -help`, версия — через `sshm -version`.

## Первое подключение

1. Нажмите `→`, чтобы перейти в каталог «Креды», затем `n` для создания профиля.
2. Укажите пользователя и выберите тип аутентификации стрелками `←` / `→`. Заполните поля для выбранного типа. Имя можно оставить пустым: приложение предложит его автоматически. Сохраните профиль через `Ctrl+S`.
3. Нажмите `←`, чтобы вернуться к соединениям, затем `n`.
4. Введите адрес сервера. Порт по умолчанию — `22`. Имя соединения можно оставить пустым: будет использован адрес.
5. В поле «Креды» нажмите `Enter`, отметьте профиль пробелом и подтвердите выбор через `Enter`. Сохраните соединение через `Ctrl+S`.
6. Нажмите `Enter` на соединении, чтобы подключиться.

Если назначено несколько профилей, можно выбрать профиль по умолчанию или выбирать его при каждом подключении. Клавиша `a` открывает выбор профиля для текущего соединения.

Папки и профили в формах выбираются из списков. Переименование профиля сохраняет его связи с соединениями. Пустой список профилей у соединения означает наследование от ближайшей родительской папки с назначенными профилями.

## Аутентификация

| Тип в интерфейсе | Что нужно указать |
| --- | --- |
| SSH-agent и стандартные ключи | Имя пользователя. OpenSSH использует текущий агент и стандартные ключи в `~/.ssh`. |
| Локальный ключ | Имя пользователя и файл ключа. Парольную фразу можно сохранить или вводить при подключении. |
| Ключ в хранилище | Имя пользователя и импортированный приватный ключ. Для зашифрованного ключа укажите парольную фразу. |
| Пароль | Имя пользователя и пароль. |

В поле ключа `Enter` открывает файловый браузер. Для ключа в хранилище доступен выбор файла или вставка содержимого. Браузер показывает скрытые файлы и папки; `←` / `Backspace` поднимает на уровень выше, `h` возвращает в домашнюю папку.

Встроенный ключ можно вставить сочетанием вашего терминала, включая строки `BEGIN` и `END`, затем подтвердить через `Enter`. `Ctrl+B` открывает браузер файлов, `Ctrl+V` читает системный буфер обмена. На macOS используется `pbpaste`, на Linux — `wl-paste`, `xclip` или `xsel`, если они доступны. В удалённом терминале используйте обычную вставку средствами терминального приложения. Содержимое ключа на экране скрыто.

Локальные ключи внутри домашней папки сохраняются как путь `~/…`. На другом устройстве файл должен находиться по тому же относительному пути. Импортированный ключ переносится вместе с хранилищем.

Профили с ключом или агентом также могут содержать пароль для дополнительного этапа аутентификации. OTP и повторные попытки после отказа вводятся интерактивно.

Пользовательский `~/.ssh/config` при подключении не читается: OpenSSH запускается с `-F /dev/null`, а адрес, порт и пользователь берутся из каталога. Используются системный `known_hosts`, текущий агент и стандартные ключи. Новый ключ сервера требует подтверждения; изменённый известный ключ блокирует подключение. Agent forwarding отключён.

## Управление

| Клавиша | Действие |
| --- | --- |
| `←` / `→`, `Tab` / `Shift+Tab` | Переключить каталог |
| `↑` / `↓`, `j` / `k` | Выбрать объект |
| `/` | Поиск по имени, адресу или тегам |
| `f` | Фильтр папки, включая вложенные папки |
| `n` / `e` / `d` | Создать / изменить / удалить |
| `Enter` | Подключиться; в остальных каталогах открыть форму |
| `a` | Выбрать профиль для подключения |
| `l` | Заблокировать хранилище |
| `P` | Сменить главный пароль |
| `S` / `Ctrl+S` | Сохранить изменения |
| `E` | Экспортировать зашифрованную копию |
| `M` | Объединить с другой копией хранилища |
| `R` | Переоткрыть хранилище |
| `q` / `Ctrl+C` | Выйти |

В формах `Tab` / `↑` / `↓` переключают поля, `Ctrl+S` сохраняет, `Esc` отменяет. В списках назначения пробел отмечает профиль, `Ctrl+U` снимает все отметки, `Enter` применяет выбор. Поиск через `/` сохраняет отметки скрытых строк.

Во время SSH клавиши обрабатываются системным OpenSSH и удалённой оболочкой. После завершения сессии менеджер восстанавливает интерфейс и показывает результат подключения.

## Синхронизация и резервные копии

Для синхронизации разместите `.sshvault` в локальной папке облачного клиента. На другом устройстве откройте синхронизированную копию с тем же главным паролем. Приложение работает с локальным файлом, доставкой изменений занимается облачный клиент.

Перед сохранением проверяется версия файла. Независимые изменения разных объектов объединяются автоматически. При конфликте приложение предлагает выбрать локальную версию или версию из файла для каждого объекта. Профиль аутентификации выбирается целиком; секреты в обзоре скрыты.

Если облачный клиент создал отдельную конфликтную копию, нажмите `M` и выберите её файловым браузером. Объединять можно копии с одинаковым ID хранилища. При импорте такой копии объекты, присутствующие только с одной стороны, сохраняются. Удаления между отдельными копиями автоматически не распространяются.

Перед каждой заменой файла рядом сохраняется предыдущая зашифрованная версия:

```text
connections.sshvault.backup-*
```

Резервную версию можно открыть через `-vault`, экспортировать или объединить с текущим файлом. Она использует пароль, действовавший в момент её создания. Резервные версии автоматически не удаляются.

Локальная блокировка согласует сохранения нескольких экземпляров на одном устройстве. При синхронизации между устройствами возможны гонки облачного клиента. Для восстановления доступны резервные версии, экспорт и объединение конфликтных копий.

## Защита данных

Весь документ, включая адреса, имена, заметки и структуру папок, зашифрован XChaCha20-Poly1305. Главный пароль обрабатывается Argon2id с параметрами 64 MiB, 3 прохода и 4 потока. Файлы хранилища и резервных версий создаются с правами `0600`.

Импортированные ключи предоставляются OpenSSH через отдельный агент в памяти. Сохранённые пароли передаются помощнику SSH_ASKPASS через локальный Unix-сокет. Секреты не помещаются в аргументы процесса или переменные окружения. Временные ресурсы аутентификации удаляются после сессии.

Главный пароль восстановить нельзя. После его смены старые резервные и облачные копии остаются доступны со старым паролем.

Формат хранилища пока не проходил независимый аудит безопасности. Go не гарантирует полного стирания всех копий секретов из памяти. Разблокированное хранилище доступно приложению на текущем устройстве.

## Разработка и проверки

Проект написан на Go с использованием Bubble Tea и Lip Gloss.

```sh
make test      # тесты с детектором гонок
make check     # go vet
make smoke     # TUI и передача терминала в PTY
make release   # macOS/Linux, arm64/amd64
```

Тесты используют временные данные. Интеграционные проверки запускают системный OpenSSH и подключают его к тестовому серверу на loopback. Терминальный тест использует контролируемую подмену `ssh` и проверяет формы, браузеры, аутентификацию, Ctrl+C, изменение размера окна и возврат в TUI. Для него нужен доступ к `/dev/tty`.

`make release` создаёт четыре бинарника в `bin/` с отключённым cgo. Версию можно указать при сборке:

```sh
make release VERSION=0.1.0
```

Исходники расположены в `cmd/sshm` и `internal/`. Сценарий проверки терминала находится в `scripts/terminal_smoke.py`.
